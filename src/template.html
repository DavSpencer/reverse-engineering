Reverse Engineering?
The mental model, the tools you need, and how everything connects — before you touch a single file.
CONCEPT The Core Idea
What RE Actually Is

Reverse engineering is reading a compiled app backwards — without the original source code. On Android, every app is a ZIP file containing compiled bytecode. You decompress it, read the bytecode, understand the logic, change it, repack it.

The bytecode is called DEX (Dalvik Executable). It's not human-readable by default, but it decompiles to a readable assembly language called Smali. That's what you edit.

The Compilation Chain — Why You Can Read It
Java / Kotlin   ← original source (you don't have this)
      ↓  javac / kotlinc
.class bytecode ← JVM bytecode
      ↓  d8 / dx
classes.dex     ← Dalvik bytecode (inside the APK)
      ↓  baksmali
Smali           ← what you read and edit
      ↓  smali
classes.dex     ← repacked after your patch

JADX reverses the chain further — DEX back to Java pseudocode. It's not perfect, but it makes complex logic readable fast.

CONCEPTS Terms You Need
  • APK — the app file. A ZIP containing DEX, resources, manifest, and native libs.
  • DEX — Dalvik Executable. The compiled bytecode Android runs.
  • Smali — human-readable assembly of DEX. What you edit in MT Manager.
  • JADX — decompiles DEX to Java pseudocode. Your reading tool, not editing tool.
  • Obfuscation — ProGuard/R8 renames classes to a.b.c. Logic unchanged, names scrambled.
  • Frida — hooks running methods at runtime without modifying the APK.
  • Signing — every APK needs a valid keystore signature. Android rejects unsigned APKs.
  • MT Manager — your on-device Swiss Army knife: APK editor, DEX editor, signer, search.

FLOW The Patching Workflow
  1. SETUP — Install MT Manager VIP, create a signing keystore, extract the target APK to a working folder.
  2. READ — Open the APK in JADX on PC. Understand the app's structure: where billing lives, what the gate methods are.
  3. HUNT — Find the exact class and method to patch using string search, call graph tracing, or Frida tracing.
  4. DECODE — If obfuscated, identify what the scrambled class names actually represent using type inference, log tags, and SDK anchors.
  5. PATCH — Open the DEX in MT Manager. Navigate to the method. Edit the Smali. Change the return value or flip the branch.
  6. SHIP — Save the APK in MT Manager. Sign it with your keystore. Uninstall the original, install your mod.
  7. DEBUG — If it crashes: read ADB logcat, find the broken method, fix the register count or bytecode, repeat.

03 · HUNT
Find Your Target
Nine methods for locating the exact method to patch. Eight methods for reading through obfuscated names. This is the hardest skill — and the most important.
ENTRY POINTS Finding What to Patch
// HOW TO USE THIS SECTIONYou rarely need just one method. The standard move: start with A (manifest) → try C (string search) → follow the call graph. If stuck, drop Frida on it. Check the decision table at the bottom.
AManifest — Declared Entry Points

The manifest declares every component Android can launch. This is the authoritative list — the OS uses it, so nothing can be hidden here.

<!-- Main launcher — always your first entry point -->
<activity android:name=".MainActivity">
  <intent-filter>
    <action android:name="android.intent.action.MAIN"/>
    <category android:name="android.intent.category.LAUNCHER"/>
  </intent-filter>
</activity>

<!-- Exported = launchable via ADB, bypasses normal flow -->
<activity android:name=".PaywallActivity"
          android:exported="true"/>

What to look for:

  • android:exported="true" — launch directly via ADB: adb shell am start -n com.app/.Activity
  • Activities with custom scheme intent-filters — deep link handlers, often skip auth
  • <service> tags — background workers, license check daemons
  • <receiver> tags — billing callbacks (INSTALL_REFERRER, purchase events)
BMainActivity Launch Chain

Every app starts at the LAUNCHER activity. Follow execution from there — hits the license check within 3–4 hops.

  1. In JADX, open the class declared as MAIN+LAUNCHER in the manifest.
  2. Read onCreate() — called first, always. Note every method it calls.
  3. Follow calls that go to other classes. Look for: auth checks, session validation, subscription status reads.
  4. Look for startActivity() calls — the condition deciding which screen launches is your gate.
// Classic gate pattern in onCreate():
if (isPremium()) {
    startActivity(new Intent(this, HomeActivity.class));
} else {
    startActivity(new Intent(this, PaywallActivity.class));
}
CString Search — Most Reliable

Strings shown in app UI are almost never obfuscated — the app needs to display them.

In JADX — Navigation → Text Search:

  • Paywall text: "Upgrade to Premium", "Subscribe", "Trial expired"
  • SharedPrefs keys: "is_premium", "subscription_status", "license_key"
  • Billing strings: "purchase", "billing", "sku", "entitlement"
  • Log tags — devs leave these matching original class names even after obfuscation

In MT Manager DEX search: search icon → String type → same searches. Works on-device without JADX.

DLogcat Live Tracing

Developers leave log statements everywhere — especially around billing and auth. Run the app with ADB logcat while triggering the locked feature.

# Filter for billing/premium keywords:
adb logcat | grep -iE "premium|license|purchase|billing|trial"

# Filter by log tag found in JADX:
adb logcat -s "PurchaseManager:D"

# Force crash near the feature, read the stack trace:
adb logcat AndroidRuntime:E *:S
// STACK TRACES ARE GOLDForce a crash near the locked feature. The stack trace gives you exact obfuscated class.method at every frame — now you have the full call chain laid out for free.
EBilling SDK Anchor

Google Play Billing and third-party billing SDKs are never obfuscated. Search their class names in JADX — they lead directly to purchase handling code.

// Search JADX for these (never obfuscated):
com.android.billingclient.api.BillingClient
com.android.billingclient.api.Purchase
com.android.billingclient.api.PurchasesUpdatedListener
com.revenuecat.purchases.Purchases
com.revenuecat.purchases.CustomerInfo
io.adapty.sdk.Adapty

Find the class that implements PurchasesUpdatedListener. The onPurchasesUpdated() method is always where purchase state gets saved. Everything Boolean nearby is a patch target.

FFrida Method Tracer

When static analysis hits a wall — trace what actually executes when you trigger the feature.

// Trace every method in a class:
Java.perform(function() {
    var cls = Java.use("a.b.c");
    cls.class.getDeclaredMethods().forEach(function(m) {
        var name = m.getName();
        try {
            cls[name].overloads.forEach(function(ov) {
                ov.implementation = function() {
                    console.log("[→] " + name + " args:",
                        JSON.stringify([].slice.call(arguments)));
                    var r = ov.apply(this, arguments);
                    console.log("[←] " + name + " =", r);
                    return r;
                };
            });
        } catch(e){}
    });
});

Inject with frida -U -n com.target.app -l tracer.js. Tap the locked feature. Console shows every method that fired and what it returned. Find the false — that's the gate.

GNetwork Traffic Interception

License checks often hit a server. Intercept the traffic to find where the response is handled.

  1. Set up mitmproxy or HTTP Toolkit. Point phone WiFi proxy to it.
  2. Disable SSL pinning first: objection -g com.target.app explore → android sslpinning disable
  3. Trigger the license check in-app. Find the request + response in the proxy.
  4. Search the endpoint URL string in JADX → finds the exact class making the call.
  5. Find the response parser that reads "is_valid" or similar. Patch its return.
HSharedPrefs Key Hunting

Most apps persist subscription state to SharedPreferences. Find the reader, patch it — or write the flag directly.

// JADX text search: "getBoolean" "getLong" "getString"
// Common keys you'll find:
prefs.getBoolean("premium_unlocked", false); // patch: return true
prefs.getLong("subscription_expiry", 0L);    // patch: return Long.MAX_VALUE
prefs.getString("license_token", null);    // patch: return "valid"
# Write directly with Frida (root not required if app is debuggable):
Java.perform(function() {
    var ctx = Java.use("android.app.ActivityThread")
        .currentApplication().getApplicationContext();
    ctx.getSharedPreferences("app_prefs", 0)
        .edit().putBoolean("premium_unlocked", true).commit();
});
IDynamic Class Loading

Advanced apps use DexClassLoader to load code at runtime. JADX finds almost nothing. Hook the loader with Frida to catch what's actually being loaded.

// Hook DexClassLoader to see what DEX files get loaded:
Java.perform(function() {
    Java.use("dalvik.system.DexClassLoader")
        .$init.implementation = function(dexPath, out, lib, parent) {
        console.log("[DexLoader] " + dexPath);
        return this.$init(dexPath, out, lib, parent);
    };
    Java.use("java.lang.Class")
        .forName.overload("java.lang.String")
        .implementation = function(name) {
        console.log("[forName] " + name);
        return this.forName(name);
    };
});
# Pull the downloaded DEX from cache and analyze it:
adb pull /data/data/com.target.app/files/plugin.dex ./
# Open in JADX like a normal APK

5Encrypted Strings — Hook the Decryptor

DexGuard/Allatori encrypt string literals. Instead of "is_premium" you see a.a(1337). Hook the decryptor with Frida to dump all strings at runtime.

// Hook the decrypt method — log every string it returns:
Java.perform(function() {
    var D = Java.use("a.a");
    D.a.overload("int").implementation = function(id) {
        var r = this.a(id);
        console.log("[str] id=" + id + " → " + r);
        return r;
    };
});

Run the app through the billing flow. You get a dump of every decrypted string with its ID. Now every a.a(N) call in JADX becomes readable.

Registers — p vs v
  • v0, v1, v2… — local variables you define
  • p0 — this (in instance methods). Static methods: p0 is first param.
  • p1, p2… — method parameters
  • .registers N — total count = all v# you use + all p# that exist
  • Long and double use two consecutive registers

# Static method, 2 params, 1 local: .registers 3
# (v0 + p0 + p1)

# WRONG register count = VerifyError crash on launch

TECHNIQUES Patching Patterns
01Always Return True

The most common patch. Gut the method body, hardcode true.

# Before:
.method public isPremium()Z
    .registers 3
    iget-object v0, p0, Lcom/app/a;->b:Landroid/content/SharedPreferences;
    const-string v1, "premium_state"
    invoke-interface {v0, v1}, Landroid/content/SharedPreferences;->getBoolean(Ljava/lang/String;Z)Z
    move-result v0
    return v0
.end method

# After:
.method public isPremium()Z
    .registers 2
    const/4 v0, 0x1
    return v0
.end method
// REGISTERSAfter gutting, update .registers to match what you actually use. Only v0 + p0 = set to 2. Wrong count = VerifyError crash.
02Flip a Single Constant

Method is already a hardcoded return — just flip the value. Least invasive patch possible.

# Find and change 0x0 to 0x1:
const/4 v0, 0x0    # false
return v0
# ↓
const/4 v0, 0x1    # true
return v0

Don't touch .registers — register count stays the same. Single character edit.

03Flip or Skip a Branch

Method branches to paywall on false. Flip the condition so it branches on true instead — or bypass the check entirely with goto.

# Original — goes to :paywall if isPremium() is false:
invoke-virtual {p0}, Lcom/app/a;->a()Z
move-result v0
if-eqz v0, :paywall   # if false → paywall
# premium code...
:paywall
invoke-virtual {p0}, Lcom/app/b;->show()V
return-void

# Option 1 — flip the condition:
if-nez v0, :paywall   # now only goes to paywall if TRUE

# Option 2 — skip check entirely:
invoke-virtual {p0}, Lcom/app/a;->a()Z
move-result v0
goto :premium         # always jump to premium code
if-eqz v0, :paywall   # now unreachable
:premium
# premium code continues...
04Early Return — Kill a Void Method

Disable an ad loader, analytics call, or license checker that returns void. Insert return-void as the very first line.

.method public loadAd()V
    .registers 1

    return-void    # ← add this as first line
    # everything below is now dead code
.end method

Set .registers 1 (just p0). Don't touch .method or .end method lines.

05NOP Sled — Neutralize Specific Lines

Replace specific instructions with nop to kill them without changing surrounding control flow. Good for disabling individual calls mid-method without touching the structure.

# Kill a license check call without removing the method:
# Original:
invoke-virtual {p0}, Lcom/app/License;->checkLicense()V

# NOP'd (3 nops = 1 invoke-virtual instruction):
nop
nop
nop
// EASIER IN MT MANAGERJust delete the invoke line in the editor and save. MT Manager will error if there's a register/stack problem. Easier than manually counting nop widths.
06Patch a String Constant

Change hardcoded strings — API endpoints, license server URLs, validation keys.

# Original — points to real license server:
const-string v0, "https://api.paywall.com/v1/check"

# Patched — points to localhost (always fails gracefully):
const-string v0, "https://127.0.0.1/check"

In MT Manager: use Functions → Search in the DEX to find URL strings in hex, then edit. Or find via DEX string search and edit in the Smali editor.

07Manifest Patches — No Code Needed

Edit AndroidManifest.xml directly in MT Manager APK Editor. MT Manager decodes binary XML automatically.

  • Add android:debuggable="true" to <application> — enables ADB debugging
  • Remove android:allowBackup="false" — enables ADB backups
  • Remove specific <uses-permission> entries to block access
  • Add android:networkSecurityConfig="@xml/nsc" + create res/xml/nsc.xml to allow HTTP traffic for traffic analysis
  • Remove android:testOnly="true" if present
08Frida Hook — No APK Modification

Patch at runtime without touching the APK. Requires root + Frida server running on device.

// Hook isPremium() to always return true:
Java.perform(function() {
    Java.use("com.app.License").isPremium
        .implementation = function() {
        console.log("[+] isPremium hooked → true");
        return true;

Save your edit, sign the APK, install it — and debug whatever breaks. Full end-to-end walkthrough at the bottom.
EDIT Making the Edit in MT Manager
The Smali Editor Flow
  1. Navigate to your target method (package → class → method). Tap it.
  2. Tap the pencil (Edit) icon — top right of the Smali viewer. Raw text editor opens.
  3. The keyboard toolbar above the keyboard has shortcuts: Tab, braces, semicolons. Use them — Smali syntax is unforgiving.
  4. Make your edit. Change 0x0 to 0x1, gut the body, flip a branch — whatever technique fits.
  5. Update .registers count if you removed or added local variables.
  6. Tap Save (checkmark). MT Manager validates the bytecode. Error = fix it. Clean = saved to in-memory DEX.
// VALIDATE BEFORE MOVING ONIf MT Manager shows an error on save, fix it before navigating away. The error message names the problem — wrong register count, bad opcode, missing return. Don't ignore it and force-save.
MT Manager Save Errors — What They Mean
ERRORCAUSE + FIX
Register count mismatchYour .registers number doesn't match registers used. Count v# used + p# parameters. Update .registers.
Unknown opcodeTypo. const/4 not const4. return-void not returnvoid. Check spelling exactly.
Invalid label referenceYou referenced :label that doesn't exist or was deleted. Check your goto/if targets.
Type mismatchReturning wrong type — returning an object from a Z method. Match return instruction to the method's declared return type.
Missing returnEvery code path must end with a return. You left a branch without one.
SAVE Write Back to APK
Save the APK
  1. After editing, back out from the method → class → package → back to APK Editor root.
  2. Tap the floppy disk icon in the APK Editor top bar. MT Manager repacks the modified DEX into the APK file on disk. Takes a few seconds for large apps.
  3. A dialog may offer to sign now. You can sign here or do it separately.
// BACKUP ORIGINALBefore patching, copy the original APK to /sdcard/Mods/originals/. If the patch breaks something you can start over without re-extracting from the installed app.
SIGN Sign the APK
Three Ways to Sign in MT Manager

Way 1 — from APK Editor: After saving, tap ⋮ menu → Sign. Uses default keystore. Creates signed copy (usually name_signed.apk).

Way 2 — from file manager: Long-press modified APK → Sign. Same result.

Way 3 — Functions: ≡ → Functions → Sign APK → select file → select keystore → sign.

// SIGN THE RIGHT FILESign the MODIFIED APK, not the original. Check file modification date or size difference. The signed output gets a _signed suffix by default — that's the one you install.
INSTALL Get It On Device
Install Flow
  1. If the original app is installed (Play Store = dev signature), uninstall it first. Android won't install over a different keystore signature. Settings → Apps → target → Uninstall.
  2. Long-press the signed APK in MT Manager → Install. Android's installer opens.
  3. Tap Install. Allow unknown sources if prompted.
  4. Launch and test your patch.
Install + Runtime Errors
ERRORCAUSE + FIX
"App not installed"Signature mismatch. Uninstall original app first, then install your mod.
"Parse error"APK is corrupt — invalid DEX. Re-patch more carefully or restore backup.
Crash on launchBad bytecode passed MT Manager's check but failed Dalvik verification. Check logcat for exact class + method.
Feature still lockedPatched wrong method, or multiple checks exist. Find all callers in JADX → Find Usage. Patch each one.
App detects mod + closesIntegrity check: app reads its own signature. Find and patch getSignatures() or PackageManager signature reads.
DEBUG When It Crashes
ADB Logcat — Read the Crash
# Filter to just fatal crashes:
adb logcat AndroidRuntime:E *:S

E/AndroidRuntime: FATAL EXCEPTION: main

  com.app.billing.a — bad method com.app.billing.a.a()Z
  → wrong register count in your patched method a()

# Example 2 — null reference:
  java.lang.NullPointerException
  at com.app.billing.a.isPremium(a.java:47)
  → you gutted too much, left a null dereference

# Example 3 — missing method:

  → you accidentally deleted a method instead of patching it

The error tells you exactly which class and method to revisit. Go back to MT Manager, find that method, fix the register count or restore what you accidentally deleted.

WALKTHROUGH Full End-to-End Example
Zero to Patched Subscription — 13 Steps

Scenario: app has a premium feature locked. Tap it — paywall appears. Goal: make it always open.

  1. Extract APK. MT Manager → ≡ → Functions → Installed Apps → find app → Extract APK → copy to /sdcard/Mods/target.apk.
  2. Scan the manifest. Long-press → Open As Archive → tap AndroidManifest.xml. Note exported activities, billing receivers, declared services.
  3. Open APK Editor. Long-press → Open With → MT Manager.
  4. Search for paywall string. Tap classes.dex → Smali Editor → search icon → String type → search the text on the paywall button or dialog. MT Manager finds the containing class and method.
  5. Navigate to the result. Tap the search result. You're in the method that shows the paywall. Read it — look for what condition triggers this code.
  6. Find the gate method. Back out to the class. Look for a ()Z method — no params, returns boolean. That's the check that gate-keeps access.
  7. Read the gate. Tap it. Confirm it returns false for non-subscribers. Note the .registers count.
  8. Edit. Tap pencil icon. Delete everything between .registers N and .end method. Type: const/4 v0, 0x1 then new line: return v0.
  9. Fix registers. Change .registers N to .registers 2. Tap Save. No errors = good.
  10. Save APK. Back out to APK Editor root → tap floppy disk → wait for repack.
  11. Sign. Long-press the modified APK → Sign → your default keystore → done. Note the _signed.apk output path.
  12. Uninstall original. Settings → Apps → your target → Uninstall.
  13. Install mod. Long-press target_signed.apk → Install. Launch. Tap the previously locked feature — it opens.
// STILL LOCKED?More than one check. Go back to JADX, right-click your patched method → Find Usage. See every caller — patch each one that gates access. Some apps check on every screen transition, not just launch.
